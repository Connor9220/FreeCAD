# ADR-010: Workholding components link to their library files

## Status
DRAFT

## Context

A **Job** shows its **Workholding** (vises, stops, clamps) beside the **Stock**, places it against the **Stock**, and gives it to the simulator for collision checks. Vises and clamps come from **Workholding Library** files: FreeCAD documents kept with the CAM assets and filled from Git repositories. Library files change over time. Jobs also move to other computers, where the library may be missing.

Options considered:

1. **Link each component to its library file** (`App::Link` across documents). One library update reaches every **Job**, **Job** files stay small, and a vise is edited in one place. The file must be on the computer. FreeCAD loads it as a second document, which shows in the tree and can appear in the "save dependent files" prompt. A change to the file changes the **Job** without warning unless something checks.
2. **Copy the solids into the Job**, as **Tool Bits** copy their **Tool Shape** body. The **Job** is portable and nothing changes under the user. Every **Job** needs an explicit update for every library change, and each carries its own copy. The **Tool Bit** library update refreshes parameters only, so there is no model-update path to reuse.
3. **One copy per library file held in the Job, components linked to that copy.** Portable, and repeated components stay cheap. Still needs an update command, and add, recovery and refresh all change.
4. **Links, plus a portable mode.** FreeCAD's "Import all links" copies the linked solids into the **Job**; such a **Job** is cut off from its library.

Other CAD and CAM packages: Fusion 360 and Onshape pin references to a version and offer an update; SolidWorks and Inventor reference files and use Pack and Go for a portable folder; Mastercam and most standalone CAM copy into the part file.

## Decision

Workholding components are links to their library files (option 1), with option 4's portable mode.

- Each **Workholding** row records the library, item id, file and sha256 it was added with (see ADR-011), and checks them when the **Job** opens.
- **Lever Clamps** re-read their file when the **Job** opens, so data cached from the file follows it.
- A **Job** whose links were imported is cut off from its library: nothing refreshes it. When an imported clamp needs a component it lacks, it copies in only that component: silently when the library file is the version it was imported from; after asking, by updating the whole clamp, when the file has changed; after asking, by downloading, when the file is missing.

## Consequences

- Gains: one library update reaches every linked **Job**; small **Job** files; a portable mode for **Jobs** that leave the computer.
- Costs: a linked **Job** needs its library files; library files show as document rows in the tree and in the "save dependent files" prompt until FreeCAD can open them as temporary documents (a core change); two modes to support.
- Open: a "Make Job portable" command with a warning, and "Link to library again", which would fetch the exact version a **Job** used by its Git commit; a preference to add **Workholding** as links or copies.
