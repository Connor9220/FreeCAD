# ADR-015: Cutting edge height says which part of a tool bit cuts

## Status
DRAFT

## Context

The simulator must tell a cut from a collision. Undercut tools (Lollipop, Keyway, Dovetail) cut with a head below a narrower neck, and a reamer or tap cuts only at its point. A shank rubbing the **Stock** is a crash, not a cut.

## Decision

`CuttingEdgeHeight` is the height of the cutting part of a **Tool Bit**, measured up from its tip. Anything above it collides.

- New **Tool Shapes**: Keyway (`CuttingEdgeHeight` = lower cutting height + neck cutting height) and Lollipop (`CuttingEdgeHeight` = where the neck meets the ball). Both derive it.
- Dovetail gains `NeckCuttingHeight`; its `CuttingEdgeHeight` stays an input and means the head.
- Reamer gains `FluteLength` for its fluted body; its `CuttingEdgeHeight` is derived as 0.
- Tap: derived as 0. Drill: derived as the tip cone's length, so a spot drill can engrave.
- 0 means only the point cuts.
- Older **Tool Bits** gain the new parameters in `migrate_parameters`, which also runs when a bit is built from its shape, before derived values are applied.

## Consequences

- Gains: the simulator shows shank and neck collisions; operations that need a ball end treat a Lollipop as one.
- Costs: a derived value cannot be overridden on those shapes.
- Parked: lens, barrel and other circle-segment cutters.
