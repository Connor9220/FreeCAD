# ADR-012: A vise's placement is the source of truth

## Status
DRAFT

## Context

A vise in a **Job** has jaws, an opening, optional parallels or steps, and a position against the **Stock**. The user sets it up the way it is set up at the machine: pick which **Stock** side sits down and which sits against the fixed jaw, then close the jaws. Early versions stored grip height and offset as numbers beside the placement; the two disagreed as soon as either moved.

Options considered:

1. **Store grip and offset as settings and derive the placement.** Explicit numbers, but two sources of truth, and too many numbers for the user.
2. **Store the placement and measure grip and offset from it.** One source of truth; the panel shows the measures as read-outs.

## Decision

The placement is the truth (option 2).

- A vise in a **Job** is one row; its components are links to its library file (ADR-010). Deleting the row or any component deletes the whole vise.
- All settings live on the row, copied from the file's VarSet. The file's jaw expressions are kept on the row and run there, because an expression in a child cannot read its parent.
- The Seat group keeps only Seated, OnParallels, Parallels and CloseJaw. Grip and offset are measured, never stored.
- A seated vise is locked: it slides along the jaws and up or down between the floor and the jaw tops; moves into the jaws and turns are refused.
- Orientation is picked as **Stock** sides (Bottom, Top, Front, Back, Left, Right) in **Job** axes, from bounding-box sides, so a cylinder works too.
- One "Vise…" command adds and seats a vise with a live preview; OK keeps the result, Cancel undoes it.

## Consequences

- Gains: what the user sees is what is stored; dragging a vise and typing values cannot disagree.
- Costs: measured values depend on the **Stock** shape's bounding box.
- Open: a vise placed relative to the **Model** for several models with their own workholding under one **Fixture** (blocked by one **Stock** per **Job**).
