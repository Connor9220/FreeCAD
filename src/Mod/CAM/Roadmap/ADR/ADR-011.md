# ADR-011: Workholding library files carry their own provenance

## Status
DRAFT

## Context

A **Workholding Library** file is downloaded, copied between computers, renamed and forked. A **Job**'s toolpaths are checked against one exact version of each file. The CAM workbench must tell where a file came from, whether it is still the same file, and where to get it again when it is missing.

Options considered:

1. **Sidecar files** (a `.json` beside each file, or a folder manifest). Easy to write. They are lost or left behind when the file is copied alone.
2. **The file stamps itself.** Its settings VarSet carries an About group. The stamp travels with the file.
3. **Nothing recorded.** The user tracks versions by hand.

## Decision

Each library file stamps itself (option 2). The About group holds: Library (the repository address it was first published in), LibraryItem (its id there), Type, Maker, Model, License, Attribution, Source. The library repository stamps a file before publishing it; a stamp written after download would change the file's sha256. A fork keeps the original stamp unless it is stamped again.

- The library's `index.json` is written from the files themselves and lists each file's size, sha256, license and thumbnail, plus every sha256 it was published with before (`history`).
- A **Job** row records the library, item, file path and sha256 when a file is added.
- When the **Job** opens: the file found with the same sha256 is used silently; a changed file is reported, since toolpaths were made against the old one; a missing file is looked for in its own library by id, then in the user's libraries, then by asking the user.
- A file holding Python objects is refused before it is opened.
- No library is configured by default; the user adds the ones they trust.

## Consequences

- Gains: provenance cannot be separated from the file; a library update is told apart from a local edit; a missing file can be found again.
- Costs: files must be stamped before they are published; an unstamped file is left out of an index.
- Open: record the Git commit beside each sha256 in `history`, so an old version can be downloaded by commit.
