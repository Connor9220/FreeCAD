# ADR-014: A tool holder is data on the tool bit

## Status
DRAFT

## Context

The simulator needs to know what is above the cutting edges: the shank, and the **Tool Holder** the **Tool Bit** is set in. A **Tool Holder** hitting the **Stock** or the **Workholding** is a crash.

At the machine, a tool holder (an ER collet chuck, a shrink-fit holder, a router's collet nut) goes in the spindle; a collet goes in the holder and a collet nut closes it. For collision checks only the outside matters: the collet is hidden inside the nut. Holders also come in long-reach and tapered (slim) versions, whose bodies reach well below the spindle nose.

Options considered:

1. **A model file per tool holder.** Exact, but each check opens and recomputes a document.
2. **An outline as data:** (radius, height) points revolved about the **Tool Axis**. All a collision check needs; nothing is opened.
3. **Where it lives:** on the **Tool Controller**, or on the **Tool Bit**.

## Decision

A **Tool Holder** is a `.fcholder` JSON file: the outline of everything from the face the bit comes out of (the exit face) up to the spindle nose, as (radius, height) points in millimeters, revolved about the **Tool Axis**. Body, collet and nut are one outline; a shrink-fit holder's exit face is its tip. Long-reach and tapered holders are taller, narrower outlines; no extra fields are needed.

Built-in tool holders ship with CAM in `Tools/ToolHolder` (ER11 to ER50, ER8 to ER25 mini, router collet nuts); files in the user's CAM assets `Tools/ToolHolder` override them. The built-in files are collet-nut outlines only; a holder body above the nut is checked only when a file draws it.

The **Tool Holder** (property `ToolHolder`) and the **Stickout** belong to the **Tool Bit**, not the **Tool Controller**: a bit is set in one holder at one stickout, measured from the exit face.

- The simulator draws the **Tool Holder** and stops at a holder or rapid strike.
- The **Tool Bit** library update shows and updates the tool holder and stickout.
- A tool holder file that cannot be read counts as no tool holder, with a warning.

## Consequences

- Gains: collision checks with no extra documents; tool holder sets shared as small files; one shape covers collet chucks, shrink-fit, long-reach and tapered holders.
- Costs: no exact holder model to show; built-in holders need body outlines added to check more than the nut.
- Open: the collet's shank range as data (an ER32 takes 2 to 20 mm), to warn when a bit's shank does not fit its tool holder.
